## Summary and actual behavior

**Code-confirmed.** [commands.rs:4250](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/commands.rs#L4250) considers an existing destination with the same basename and byte length already ingested; equal length does not establish identical content. If lengths differ, [commands.rs:4258](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/commands.rs#L4258) calls `fs::copy` onto the existing file, silently overwriting it. The `.txt` sidecar has the same overwrite behavior. A subsequent upsert can associate the replacement with the original record and its organization.

Reproduction condition: two generators produce distinct `output.png` files into a pipeline whose managed destination already contains that name. Fix through a common no-clobber publication service, explicit collision policy, content verification, and per-item receipts. 

The plain managed-import fallback at [commands.rs:884](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/commands.rs#L884) also assumes that same basename plus equal byte length means identical content. It reuses the existing file/record instead of copying a distinct equal-length asset. This path renames differing-length collisions, so its defect is silent false deduplication rather than the pipeline's overwrite behavior. Include both import paths in the collision acceptance tests.

## Environment and evidence

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.
- Review host: Windows; the inspected application was launched from the repository root with `pnpm run tauri dev`.
- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.

## Reproduction or validation scenario

1. Use synthetic source and managed pipeline folders; place different valid images named `output.png` in each.
2. Run the manual pipeline harvest with different source/destination byte lengths.
3. Repeat with distinct equal-length files, then with plain managed import; include `.txt` sidecars.

## Expected behavior

Distinct content is preserved under distinct destination names; deduplication requires content identity.

## Acceptance criteria

- [ ] Use no-clobber publication for assets and sidecars across pipeline and plain managed import.
- [ ] Verify content before reusing an existing file or ID; do not infer identity from byte length.
- [ ] Test different-size collisions, equal-size different content, identical content, partial publication and retry.
