## Summary and actual behavior

**Code-confirmed.** [legacy_migration.rs:254](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/legacy_migration.rs#L254) loads the legacy config and ignores both credential migration and destination save errors. [config_store.rs:99](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/config_store.rs#L99) rejects saving a nonzero legacy revision into an absent destination whose default revision is zero. The coordinator still appends a `config` artifact with status `success` even when no destination config exists.

Additionally, `config_store::load` may rewrite the legacy source to protect plaintext secrets, so this supposedly source-preserving migration reads through a mutating API. Cleanup preview at [legacy_migration.rs:389](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/legacy_migration.rs#L389) marks config and models eligible after checking database health, without validating those destination artifacts. Current Vue code has no cleanup consumer, so cleanup exposure is latent; the migration false-success path itself is active.

## Environment and evidence

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.
- Review host: Windows; the inspected application was launched from the repository root with `pnpm run tauri dev`.
- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.

## Reproduction or validation scenario

1. Prepare a supported legacy config with a nonzero revision and no Omera destination config.
2. Invoke the legacy migration coordinator; compare its receipt with the destination configuration.
3. Inspect whether reading the legacy config changes its bytes, and whether cleanup eligibility validates config/model destinations.

## Expected behavior

Migration is source-preserving, reports every failed artifact accurately and permits cleanup only after artifact-specific destination validation.

## Acceptance criteria

- [ ] Read legacy config without mutating the source and handle revisions explicitly during migration.
- [ ] Propagate credential/save errors and verify destination artifacts before recording success.
- [ ] Require validated destinations and separate in-app cleanup approval; test nonzero revisions, missing models and credential failures.
