## Summary and actual behavior

**Reproduced.** [export.rs:271](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/crates/omera-scan/src/export.rs#L271) suppresses `TextPrompt` only for `StripAll`; `StripPromptOnly` and `StripAllAiMetadata` still export the confidential positive prompt or raw metadata as `.txt`. The export dialog allows these combinations. Both policy probes fail with a synthetic embedded prompt.

The existing Rust export test at [export.rs:786](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/crates/omera-scan/src/export.rs#L786) explicitly expects this leaking sidecar under `StripAllAiMetadata`, even while checking that the HTML showcase removes the prompt.

## Environment and evidence

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.
- Review host: Windows; the inspected application was launched from the repository root with `pnpm run tauri dev`.
- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.

## Reproduction or validation scenario

1. Create a synthetic PNG with an A1111 `parameters` text chunk containing `confidential prompt`.
2. Call `process_single_image` using PNG output, `TextPrompt` sidecar and `StripPromptOnly`.
3. Repeat with `StripAllAiMetadata`; inspect the returned sidecar bytes.
