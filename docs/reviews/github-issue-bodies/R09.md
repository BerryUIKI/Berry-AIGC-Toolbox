## Summary and actual behavior

**Reproduced.** [db.rs:688](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/crates/omera-storage/src/db.rs#L688) changes path/container/size/mtime but does not update extracted metadata. A 64×32 source resized to 32×16 retains width 64 in the library; `StripAll` retains the original confidential prompt in its database record.

This breaks Inspector values and metadata-dependent searches/filters, and allows later exports to use stale prompt data.

## Environment and evidence

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.
- Review host: Windows; the inspected application was launched from the repository root with `pnpm run tauri dev`.
- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.

## Reproduction or validation scenario

1. Index a synthetic 64×32 PNG containing a prompt in a temporary managed folder.
2. Run `execute_library_batch_transform` with JPEG output and `max_edge: 32`; read the stored record.
3. Repeat using `TransformMetadataPolicy::StripAll` and inspect the stored prompt.
