## Summary and actual behavior

**Reproduced.** [omera-scan/Cargo.toml:16](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/crates/omera-scan/Cargo.toml#L16) enables AVIF encoding, but the built image decoder does not support AVIF. A generated AVIF derivative then fails the actual thumbnail service with `The image format Avif is not supported`. The transform's AVIF validation checks container branding instead of performing a supported decode.

## Environment and evidence

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.
- Review host: Windows; the inspected application was launched from the repository root with `pnpm run tauri dev`.
- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.

## Reproduction or validation scenario

1. Transform a synthetic PNG using `TransformFormat::Avif`.
2. Pass the generated file to `omera_scan::thumbnail::generate_thumbnail` using the same build.
3. Observe `The image format Avif is not supported`.

## Expected behavior

A format offered for managed library transformation can be decoded by the shipped thumbnail/preview path, or its export-only limitations are explicit.

## Acceptance criteria

- [ ] Package a supported AVIF decoder for every supported target or gate AVIF as export-only.
- [ ] Validate a supported decode rather than only the AVIF container brand.
- [ ] Test generation, import, thumbnail, preview and re-export with the shipped dependency configuration.
