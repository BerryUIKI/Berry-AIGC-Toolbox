## Summary and actual behavior

**Code-confirmed.** [cloud_sync.rs:378](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/cloud_sync.rs#L378) uses the folder basename, and [cloud_sync.rs:411](https://github.com/BerryUIKI/Omera/blob/bdac8fbcdbac5535075e091453b77c3afe518ba5/src-tauri/src/cloud_sync.rs#L411) constructs `prefix/basename/relative_path`. Two roots such as `D:\a\outputs` and `E:\b\outputs` both publish `outputs/image.png`. Different library files can overwrite the same remote object or be skipped as if already synchronized.

- Baseline: Omera 0.4.3, `dev` at [`bdac8fb`](https://github.com/BerryUIKI/Omera/commit/bdac8fbcdbac5535075e091453b77c3afe518ba5); SQLite schema 15.

- Evidence strength is stated above. For code-confirmed scenarios, the steps below describe a targeted validation scenario rather than a completed end-to-end reproduction. Remote-provider, destructive real-library and cross-platform scenarios were not exercised.
