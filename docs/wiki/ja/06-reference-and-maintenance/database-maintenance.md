# データベースとキャッシュのメンテナンス

Omera は、日常的なメンテナンスを最小限に抑えるよう設計されています。しかし、数万点もの作品を整理、削除、変更していくにつれ、定期的なデータベースの最適化（VACUUM）やキャッシュ管理を行うことで、常に最高のパフォーマンスを維持できます。

---

## 2. SQLite の最適化・圧縮 (`VACUUM`)

### データベースの断片化とは？
画像の削除、タグの解除、スタックの分解などを行うと、SQLite はディスク上の `.db` ファイルを即座に縮小するのではなく、該当するディスク領域を「空きページ（Freelist）」として再利用待ち状態にします。

### `VACUUM` の実行：
- **「VACUUM を実行」** をクリックすると、SQLite ネイティブの最適化ルーチンが実行されます。
- Omera はデータベースファイルを連続したクリーンな構造に再構築し、空きページを回収してディスク上のファイルサイズを削減するとともに、クエリプランナーを最適化します。
- **安全性**: 最適化処理は完全にトランザクション保護されています。処理中に万が一電源が切れても、SQLite のロールバック機能によりデータが破損することはありません。

## 3. データベースのバックアップと復元

### ローカルバックアップの作成 (`backup_database`)
- **「バックアップを保存…」** をクリックすると、整合性の取れた非ロックバックアップが作成されます。
- Omera は SQLite のオンラインバックアップ API を利用するため、アプリを使い続けながら安全にスナップショットを取得できます。

### バックアップからの復元 (`restore_database`)
- 新しい PC へのデータ移行時や、誤った一括操作を取り消したい場合、**「復元を実行…」** をクリックします。
- Omera は現在のデータベースの安全なロールバックコピーを自動生成した上で、指定したバックアップファイルで置き換え、復元されたライブラリ状態を即座に再読み込みします。

## 4. サムネイルキャッシュ管理と自動破棄 (LRU)

サムネイルは高効率な WebP ファイルとして `<app_data_dir>/thumbnails/` に保存されます。

### キャッシュ上限容量（バジェット）の設定：
- **環境設定 > ギャラリー（表示と安全保護）** で、**Thumbnail Cache Budget**（デフォルト: `2048 MB` / 2 GB）を設定できます。
- Omera は `thumbnail_cache_entries` テーブルですべてのサムネイルの最終アクセス日時を記録しています。
- サムネイルの総容量が設定上限を超えると、**LRU（Least Recently Used：最も古くアクセスされた順）** ポリシーに従って古い階層のファイルが自動的に破棄されます。

### キャッシュの手動消去：
- ドライブの空き容量を即座に確保したい場合は、**「サムネイルキャッシュを消去」** をクリックします。
- キャッシュされているすべての WebP ファイルが削除され、管理テーブルがクリアされます。サムネイルは今後フォルダを閲覧した際に必要に応じてオンデマンドで再生成されます。

---

## 5. サムネイル診断モーダル (`ThumbnailDiagnosticsModal.vue`)

パフォーマンス監視やデバッグを行う場合：
- **環境設定 > ギャラリー > 診断情報** を開くと以下が確認できます：
  - 稼働中の Rayon ワーカースレッド数（例: `4スレッド稼働中`）。
  - 保留中のサムネイル生成キュー数。
  - 完了したジョブ数とキャンセルされたジョブ数。
  - メモリ内 LRU キャッシュのヒット率。
