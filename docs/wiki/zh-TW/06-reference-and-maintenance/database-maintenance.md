# 資料庫與快取維護

Omera 專為長效低維護運行而設計。然而，當您管理、刪除、標記與異動數以萬計的生成作品時，定期執行資料庫物理結構壓縮與快取清理，能確保應用程式始終處於極致巔峰效能。

## 2. SQLite 物理壓縮 (`VACUUM`)

### 何謂資料庫碎片化？
當您在圖庫中刪除圖片、解除相簿關聯或解散堆疊時，SQLite 不會立刻縮減磁碟上的 `.db` 實體檔案，而是將這些被刪除的資料區塊標記為「閒置頁」(Freelist)。

### 執行 `VACUUM` 壓縮：
- 點擊 **「執行 VACUUM」** 按鈕，即可觸發 SQLite 原生壓縮程序。
- Omera 會在磁碟底層重新重組資料庫檔案，消除所有零散閒置頁，釋放實體磁碟容量並最佳化查詢規劃器的索引走訪效能。
- **絕對安全性保障**：Vacuum 過程具備完整的資料庫交易性 (Transactional)。即使在壓縮中途遭遇突發斷電，SQLite 也會自動安全回滾，絕無資料損毀之虞。

## 3. 資料庫備份與復原

### 建立本機快照備份 (`backup_database`)
- 點擊 **「匯出備份…」**，即可為目前資料庫產出一份校驗完畢、完全無鎖的快照複本。
- Omera 運用 SQLite 的線上備份 API，備份期間軟體可照常檢視、檢索或生成入庫，完全無需暫停使用。

### 從備份快照復原 (`restore_database`)
- 當需在新電腦上重建圖庫或復原誤操作時，點擊 **「復原資料庫…」**。
- Omera 會先在本地自動產生當前圖庫的安全回滾複本，再將備份檔案換入生效，並立即無縫刷新整個工作室圖庫。

## 4. 縮圖快取管理與 LRU 淘汰機制

高解析度 WebP 縮圖皆集中儲存在 `<app_data_dir>/thumbnails/` 目錄中。

### 可自訂的磁碟快取預算：
- 在 **偏好設定 > 顯示與安全保護** 中，您可以設定 **縮圖快取配額**（預設：`2048 MB` / 2 GB）。
- Omera 會在資料庫的 `thumbnail_cache_entries` 表中精準記錄每一張縮圖的最後存取時間戳記。
- 當縮圖總佔用空間超過預算門檻時，系統會依據 **LRU (Least Recently Used)** 策略自動淘汰並刪除最久未被瀏覽的歷史縮圖。

### 即時手動清理快取：
- 若急需釋放硬碟空間，可隨時點擊 **「清理縮圖快取」**。
- Omera 將清空磁碟上的 WebP 檔案並重設對應快取紀錄。當您再次瀏覽特定資料夾時，系統會在背景以延遲載入 (Lazy Load) 模式按需重新生成。

## 5. 縮圖解碼診斷面板 (`ThumbnailDiagnosticsModal.vue`)

針對高階調校與效能排查：
- 開啟 **偏好設定 > 顯示與安全保護 > 診斷資訊**，即可即時查閱：
  - 目前活動中的 Rayon 背景工作執行緒數量（例如 `4 個背景執行緒運作中`）。
  - 待處理的縮圖產生佇列積壓深度。
  - 已完成 vs 已取消的圖片生成任務數。
  - 記憶體層級的 LRU 快取命中率與延遲指標。
