## Evidence and source pointers

**Code-confirmed.** When an existing destination has a different byte length, pipeline harvesting copies onto its path with fs::copy. That overwrites the previously managed image; the same publication path overwrites an existing text sidecar. A database upsert can leave the replacement associated with the previous asset's curation.

1. In temporary pipeline source/destination folders, create distinct valid output.png files with different byte lengths.
2. Run manual harvesting and compare destination bytes and its original database record.
3. Repeat with an existing output.txt sidecar.
