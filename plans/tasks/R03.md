## Expected behavior

Cleanup preserves a source unless the verified managed destination exists and the source still matches the ingested item.

## Recommended implementation

1. Bind deferred cleanup receipts to validated destination identity and the originally ingested source identity, not only a pathname/deadline.
2. At execution, revalidate destination existence/content and unchanged source identity; fail safely or retain the source when proof is missing.

## Targeted validation

- [ ] Delete or replace the destination before expiry and verify the remaining source is retained.
- [ ] Replace the source at the same path, change external-root access or corrupt the receipt; verify no newer/user-shared file is removed.

## Issue acceptance (preserved verbatim)

- [ ] Record and revalidate source identity and destination content immediately before cleanup.
- [ ] Use `target_file_id` and a durable receipt; retain a deferred/failed state when validation fails.
- [ ] Test destination loss, replaced source, trash failure and restart; exclude external vaults and unrelated media.
