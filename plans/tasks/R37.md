## Expected behavior

Add a one-click toggle at a stable location in the main gallery toolbar, near the view-mode controls. Show both an icon and explicit localized state, such as **Masking on** / **Content visible**. The control should remain available without selecting an image and at normal/narrow window sizes.

Recommended preference model: Settings retains the startup default; the quick control changes the current viewing session. The interface should distinguish the active session state from the saved startup default.

Enabling masking should immediately conceal sensitive items again, including images temporarily revealed earlier in that session. Disabling masking should visibly indicate that content is exposed. This is a presentation control; it does not change an image's NSFW classification or the library's metadata.

## Recommended implementation

1. Add a stable, one-click toolbar masking toggle with localized explicit state and accessible toggle semantics; keep it usable without a selection.
2. Use session presentation state while Settings retains the startup default. Explicit enabling clears temporary reveals; the control never modifies NSFW classification. Add a conflict-checked documented shortcut that ignores focused inputs/modals as appropriate.

## Evidence and source pointers

The global sensitive-content masking preference is available inside Settings, but the main gallery has no readily accessible control for changing it. Users switching between private viewing, a shared workspace and screen sharing must interrupt browsing and navigate through the settings dialog.

The user raised this usability concern during the native application review. Source inspection confirms the preference is exposed in SettingsModal and passed from App.vue into VirtualGrid, while the gallery toolbar provides sorting, zoom and view-mode controls without a masking toggle.

This issue covers quick access and feedback for the masking control. Existing Table-mode enforcement is tracked in #252, and classification false positives in #296. Those reports remain separate; the toolbar control must not imply that unresolved presentation surfaces are protected.
